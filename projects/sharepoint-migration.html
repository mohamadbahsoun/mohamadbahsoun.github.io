SharePoint 2013 → SharePoint Subscription Edition Migration

A structured migration scenario covering environment assessment, farm architecture, SQL Server dependencies, content migration, application dependencies, testing and production cutover.

Project Overview

This project presents a practical approach to planning a SharePoint migration from a legacy SharePoint 2013 environment to a modern SharePoint Subscription Edition environment.

Starting Environment

SharePoint 2013 farm supporting collaboration, document management, internal applications and business workflows.

Target Environment

SharePoint Subscription Edition environment designed with updated server infrastructure, supported components and a structured farm architecture.

Primary Goal

Move SharePoint workloads while maintaining business functionality and minimizing disruption to users.

Key Dependencies

SharePoint configuration, SQL Server databases, service applications, customizations, authentication, workflows and third-party components.

Migration Planning Note

A SharePoint migration should begin with an assessment of the existing environment and the supported migration path. The exact implementation approach depends on the source version, target version, customizations, databases, integrations and business requirements.

Environment Assessment

Before migration, the existing farm needs to be documented and analyzed. The assessment identifies dependencies that could affect the migration or require remediation.

  • SharePoint farm topology
  • Web applications
  • Site collections
  • Content databases
  • Service applications
  • SQL Server configuration
  • Authentication configuration
  • Custom solutions and features
  • Third-party components
  • Workflows and automation
  • Search configuration
  • External integrations

Migration Strategy

The migration is treated as a controlled project rather than a simple server replacement.

1

Discovery

Document the existing SharePoint farm, databases, applications, customizations and dependencies.

2

Assessment

Identify unsupported components, obsolete customizations, third-party products and workloads requiring remediation.

3

Target Architecture

Define the target SharePoint farm, SQL Server environment, service applications, authentication and operational requirements.

4

Test Migration

Perform a migration in a non-production environment and validate content, applications, permissions and workflows.

5

Business Validation

Verify that important business functions continue to work and that users can access required content and applications.

6

Production Cutover

Execute the approved migration and cutover plan during an agreed maintenance window.

7

Post-Migration Validation

Validate sites, documents, permissions, search, workflows, integrations and user access after migration.

SQL Server Considerations

SQL Server is a critical component of a SharePoint farm. Migration planning therefore includes database discovery, capacity planning, backup strategy and validation.

Database Inventory

Identify SharePoint content databases, configuration databases and service application databases associated with the environment.

Capacity Planning

Review database sizes, growth patterns, storage requirements and expected future capacity.

Backup & Recovery

Confirm that database and SharePoint recovery procedures are available before migration activities.

Performance

Review SQL Server resources and configuration to ensure that the target environment can support expected SharePoint workloads.

Application & Workflow Dependencies

Migration planning must account for components outside the standard SharePoint platform.

  • Custom SharePoint solutions
  • Farm solutions
  • Custom web parts
  • SharePoint Designer workflows
  • Third-party workflow platforms
  • Nintex workflows where applicable
  • External applications
  • Authentication integrations
  • Scheduled jobs and scripts
  • Custom APIs and integrations

Testing & Validation

Testing is performed at multiple levels before production cutover.

Infrastructure Testing

Validate SharePoint servers, SQL connectivity, service applications and authentication.

Content Testing

Verify sites, libraries, lists, documents, metadata and permissions.

Application Testing

Test custom applications, web parts, integrations and business-specific functionality.

Workflow Testing

Validate important workflows and automation processes, including third-party workflow dependencies.

Search Testing

Confirm that required content is indexed and can be discovered through SharePoint search.

User Acceptance Testing

Business users validate the functions they rely on before the production cutover is approved.

Cutover Planning

A controlled cutover reduces operational risk and gives the technical team a clear sequence of activities. 

Pre-Cutover
------------------------------
[ ] Confirm migration readiness
[ ] Confirm backups
[ ] Confirm maintenance window
[ ] Notify users
[ ] Confirm rollback plan
[ ] Freeze changes where required


Migration
------------------------------
[ ] Execute migration activities
[ ] Validate databases
[ ] Validate SharePoint configuration
[ ] Validate web applications
[ ] Validate authentication


Post-Cutover
------------------------------
[ ] Test user access
[ ] Test documents
[ ] Test permissions
[ ] Test workflows
[ ] Test search
[ ] Test integrations
[ ] Monitor environment
